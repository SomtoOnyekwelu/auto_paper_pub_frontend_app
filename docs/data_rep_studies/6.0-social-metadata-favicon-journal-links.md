`src/config/brand.ts`, `src/layouts/Layout.astro`,
`src/pages/journals/[journal_initials]/[slug].astro`

Purpose: WhatsApp/OG link previews on `https://amssr.org/journals/*` links lack
the AMSSRN logo and OpenGraph metadata; the fav icon set is SVG-only (no ICO
fallback); the article page hardcodes the archive href instead of using the

## Phase 2 — Conceptual Mapping (domain insights)

- **Empty Slug Trap (Part 3 §7)**: `path` passed to `absoluteSiteUrl` must
  always be root-relative (begin with `/`). Passing a path without a leading
  slash would be resolved as a *relative* URL against the base, producing
  `https://amssr.org/journals/<last-segment>/path` — a silent double-up.
  The `new URL(path, base)` constructor handles absolute paths correctly: a
  leading `/` always replaces the entire path of `base`.
- **Single `/journals/` prefix discipline**: `PUBLIC_ASSET_PREFIX = "/journals"`
  is the single source of truth. `assetsPrefix` in Astro handles bundled CSS/JS;
  `_redirects` 200-rewrites handle `public/` assets. Neither mechanism adds a
  *second* `/journals/`. The social image path `ogImageUrl` is
  `PUBLIC_ASSET_PREFIX + "/assets/social/..."` = `"/journals/assets/social/..."`
  — exactly one prefix. `absoluteSiteUrl(ogImageUrl, site)` produces
  `https://amssr.org/journals/assets/social/...` — exactly one prefix.
- **Abstract Visibility**: on the article page, `description` = the
  `citation_abstract` (which is already visible in `<body>` as text). OG
  `og:description` therefore mirrors body content — no duplicate content
  penalty risk.
- **DOI/ORCID/ISSN format truths** (already handled by SeoHead.astro, which is
  NOT modified): social meta does not re-emit citations; it only duplicates
  `title` / `description` for link previews.
- **Brand string "AMSSRN"`: the domain is `amssr.org` (renamed from `amssrn.org`
  per mentor directive), but the visible brand string, logo filenames, and alt
  texts remain "AMSSRN". `og:site_name` is the literal `"AMSSRN"`, NOT
  `"amssr"`.
- **No `base`**: Astro has no `base` configured. `Astro.url.pathname` already
  carries the `/journals/` prefix from the route folder. No double-prefixing.
- **Asset existence invariant**: the social image must exist at the *source*
  path (`public/assets/social/amssrn-og.png`), not at the proxied path
  (`/journals/assets/social/amssrn-og.png`). The `_redirects` 200-rewrite is
  deployment-time; the test checks the filesystem.

## Testing Notes (discovered during implementation)

- **`fc.stringMatching` rejects the `i` regex flag**: fast-check 3.19's
  `stringMatching` generator throws when the regex has the `i` flag. Tier-3
  fuzzers use explicit `[a-zA-Z]` character classes instead.
- **`//` protocol-relative trap**: `new URL('//', base)` throws
  `TypeError: Invalid URL` because the WHATWG parser interprets `//` as a
  protocol-relative reference. The Tier-3 path generator was tightened to
  require a non-slash character after the initial `/`, preventing `//` from
  being generated.
- **PNG dimension verification**: the Tier-1 PNG-dimension test reads the IHDR
  chunk directly via `Buffer.readUInt32BE` (no PIL/Pillow dependency in the
  test runtime).
- **All 20 SEO tests pass**; existing `data-rep.test.ts` (21) and
  `galley-function.test.ts` (3) remain green — 44/44 total.
