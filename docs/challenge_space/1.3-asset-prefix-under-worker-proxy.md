# Challenge: Asset URL Prefixing Under the Cloudflare Worker Reverse Proxy

ID: 1.3 · Status: Resolved (assetsPrefix + _redirects) · Last Updated: 2026-08-12

## The Core Problem

The site is served at `https://amssr.org/journals/*` through a Cloudflare Worker
reverse proxy (the Worker fetches `for-redirect-to-journals-on-pages.amssr.org`
which maps to the `ajournals` Cloudflare Pages project). The Pages build output
must satisfy two simultaneous constraints:

1. **Files must physically live at `dist/journals/*`** — because the Worker
   fetches `/journals/*` paths, and Pages serves files from `dist/` by path.
2. **Asset URLs (CSS/JS/images/favicon) must be `/journals/*`-prefixed** — so the
   browser's asset requests also route through the Worker and resolve.

These two constraints conflict: Astro's `base` option prefixes *URLs* but not the
*filesystem layout*, so naively using `base` breaks one or the other.

## Constraints & Boundaries

- Google Scholar requires all content (HTML + PDF) in the same subdirectory
  (`/journals/*`). Asset URLs must not "leak" the Pages origin.
- The Worker proxy is the single entry point; it does not strip or rewrite paths.
- `trailingSlash: 'always'` is a hard constraint (Cloudflare Pages 301-redirects
  slashless folder paths; `'never'` creates an infinite redirect loop).
- No redirect chains (301/302) for assets — SEO-neutral 200 rewrites only.

## The Trial-and-Error History (complete, for future agents)

This challenge was paused and resumed multiple times. The full record:

### Attempt 1 — `base: '/journals'` + pages moved up one level (FAILED)

**Approach:** Move `src/pages/journals/*` → `src/pages/*` (flat) and set
`base: '/journals'`, assuming Astro would preserve `dist/journals/*`.

**Result:** `base` prefixed *URLs* but NOT the output directory. Build produced
`dist/grjbm/*`, `dist/index.html` (flat). The Worker fetched `/journals/grjbm/*`
which did not exist in `dist/`, so Pages returned a fallback to the root
`index.html` (the journals directory). The browser then bounced every article
back to `/journals/`. **Root cause: `base` does not restructure `dist/`.**

### Attempt 2 — `base` + hardcoded refs via `new URL(path, Astro.site).pathname` (FAILED)

**Approach:** Keep `base`, replace hardcoded root-relative refs with
`new URL('/logo.png', Astro.site).pathname` (a colleague's advice).

**Result (empirically verified 2026-08-12):** `new URL(path, Astro.site).pathname`
returns the path relative to the site *root*, **ignoring `base`** — the logo
emitted `/assets/...` not `/journals/assets/...`. Bundled CSS/JS *did* get the
`/journals/` prefix (Astro 7 prefixes bundled imports with `base`), but the
favicon concat produced `/journalsfavicon.svg` (missing slash), and the
`dist/` layout remained flat. **Root cause: `new URL()` does not respect `base`.**

### Attempt 3 — `base` + `dist/journals/` files (FAILED — double prefix)

**Approach:** Move pages back under `src/pages/journals/*` (restore
`dist/journals/*`) while keeping `base: '/journals'`.

**Result:** Files correctly at `dist/journals/*`, assets correctly
`/journals/*`-prefixed, **but** the canonical links and the sitemap became
**double-prefixed** (`/journals/journals/...`). The sitemap plugin joins
`site + base + route`, and since routes already carry `/journals/` from the
folder structure, the base doubled it. **Root cause: `base` + routes that
already contain the prefix = double prefix.**

### Attempt 4 — no `base` + `_redirects` 200 rewrites (WORKING, superseded)

**Approach:** Remove `base` entirely. Pages at `src/pages/journals/*` (so
`dist/journals/*` files exist), assets root-relative (`/assets/*`,
`/favicon.svg`), and add `public/_redirects` 200 rewrites mapping
`/journals/assets/*` → `/assets/*`, `/journals/favicon.svg` → `/favicon.svg`.

**Result:** Routes correct, files correct, no double prefix, no redirect chain.
The public assets (favicon, logo) resolved via `_redirects`. **But bundled CSS/JS
were root-relative (`/_astro/*`)** — the `_redirects` handled those too via
`/journals/_astro/*` → `/_astro/*`.

### Attempt 5 — `build.assetsPrefix: '/journals'` + `_redirects` for public assets (FINAL)

**Approach:** Discovered Astro 7's documented **`build.assetsPrefix`** option —
it prefixes *only asset URLs* (bundled CSS/JS) without touching routes or the
sitemap. Combined with `_redirects` for the public/ assets (favicon, logo)
which `assetsPrefix` does NOT cover.

**Result (verified):**
- Stylesheet: `/journals/_astro/papers.C3jXgS1_.css` ✅ (assetsPrefix)
- Favicon: `/favicon.svg` → rewritten by `_redirects` to serve at `/journals/favicon.svg` ✅
- Logo: `/assets/logos/amssrn-logo-512.png` → rewritten by `_redirects` ✅
- Canonical: single `/journals/grjbm/18-...` ✅
- Sitemap: single `/journals/...` (no double prefix) ✅
- Routes: `dist/journals/*` files exist ✅

## The Hand-Sanitizer Solution

**`build.assetsPrefix: '/journals'`** is the native, built-in, structurally
simplest abstraction that prefixes bundled assets without the `base`
side-effects (route restructuring + sitemap double-prefix). The remaining
public/ assets (favicon, logo) are handled by a **200 rewrite** in
`public/_redirects` (SEO-neutral, no redirect chain).

## Configuration (committed)

```js
// astro.config.mjs
export default defineConfig({
  site: 'https://amssr.org',
  trailingSlash: 'always',
  output: 'static',
  build: {
    assetsPrefix: '/journals',
  },
  integrations: [sitemap()],
  // ...
});
```

```txt
// public/_redirects
/journals/assets/*   /assets/:splat   200
/journals/_astro/*   /_astro/:splat   200
/journals/favicon.svg  /favicon.svg   200
/journals/favicon.ico  /favicon.ico   200
/journals/robots.txt   /robots.txt    200
```
