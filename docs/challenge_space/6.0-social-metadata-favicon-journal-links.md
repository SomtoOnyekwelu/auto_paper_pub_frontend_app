# Challenge: Social Metadata, Favicons, and Journal Links

ID: 6.0 · Status: **Solved (MVP Standard)** · Last Updated: 2026-08-12

## The Core Problem

Three user- and crawler-facing issues compound on the AMSSRN journal pages:

1. **No OG / Twitter Card metadata**: when a link to `https://amssr.org/journals/...`
   is shared on WhatsApp, Facebook, or X/Twitter, the link preview shows no logo,
   no title, and no description — just a bare URL with the host's favicon.
2. **SVG-only favicon**: Layout.astro emits only `<link rel="icon" type="image/svg+xml">`.
   Older browsers and some link-preview renderers do not render SVG favicons; an ICO
   fallback is required.
3. **Hardcoded journal archive href**: `[slug].astro` constructs the "back to journal"
   link via an inline template literal (`/journals/${paper.journal_initials}/`) instead
   of calling the shared `journalArchiveUrl()` helper from `src/utils/papers.ts` — a
   duplication-on-write anti-pattern that risks drift.

## Constraints & Boundaries

- **Domain rename is URL-only** (mentor directive 2026-08-11): `amssrn.org` →
  `amssr.org` affects URLs only. The visible brand string "AMSSRN", logo filenames
  (`amssrn-logo-512.png`, `amssrn_logo.png`), and `alt`/`aria-label` text stay
  **unchanged**. `og:site_name` is the literal `"AMSSRN"`.
- Only the frontend repo. Do NOT touch the backend repo, docs, or
  `deployment-config.mjs` (`PUBLIC_ASSET_PREFIX` stays `"/journals"`).
- Preserve asset-prefix topology: NO astro `base`, keep `trailingSlash: 'always'`,
  keep `_redirects` as-is (no new redirect chains). The existing
  `/journals/assets/*  /assets/:splat  200` rewrite already covers the OG image;
  the existing `/journals/favicon.ico  /favicon.ico   200` rewrite already covers
  the ICO fallback.
- Do NOT modify `SeoHead.astro`'s Highwire output — social meta is a separate
  component.
- `Astro.site` (`https://amssr.org`) is the single source of truth for the domain.
  NEVER hardcode `https://amssr.org` (or `https://amssrn.org`) inside any component.

  Property-Based).

  directory (type=website) pages.

## Exclusion Criteria

- Author pages, search, and other MVP-2 features.
- Changes to SeoHead.astro's Highwire meta tags.
- Any backend or deployment-config changes.
- New `_redirects` rules (the existing asset wildcard already covers the OG image).

## History & Decisive Decisions

- **SocialMeta as a separate component**: overloading SeoHead.astro with OG tags
  would violate its Challenge Space (Highwire-only, "Google Scholar indexing").
  A new, focused component preserves Single Responsibility and makes social meta
  testable in isolation.
- **OG image dimensions**: 1200×630 px — the canonical Facebook/LinkedIn/X OG
  preview size. Generated locally from `amssrn-logo-512.png` via a Python/Pillow
  script (no network fetch, no binary stdout). The logo is centered on a white
  canvas with no text — the page title/description provide the textual content.
- **URL helper as a pure module** (`seo.ts`): the existing `data-rep.test.ts`
  conventions require tests to target pure/data modules only (never `.astro`
  files). By extracting absolute-URL construction into `seo.ts`, the entire
  invariant chain — single `/journals/` prefix, no double-prefixing, correct
  OG image path — is unit-testable in vitest without spinning up Astro.
- **`fc.stringMatching` `i`-flag limitation**: fast-check's `stringMatching`
  generator does not support the `i` regex flag. Tier-3 fuzzers use explicit
  `[a-zA-Z]` character classes instead.
- **`//` protocol-relative trap**: `new URL('//', base)` throws `TypeError`
  because the WHATWG parser interprets `//` as a protocol-relative reference.
  The Tier-3 path generator was tightened to require a non-slash character after
  the initial `/`, preventing `//` and `/\n` from being generated.

## Living Implementation Plan

### Strategy Overview

1. Add `ogImageUrl` to `src/config/brand.ts` (single source of truth for the
   OG asset path, reusing `PUBLIC_ASSET_PREFIX`).
2. Create `src/utils/seo.ts` with pure functions `absoluteSiteUrl` and
   `socialImageUrl` — importable by both `.astro` components and vitest.
3. Generate the 1200×630 OG PNG from the existing logo.
4. Create `src/components/SocialMeta.astro` — receives `type`, `title`,
   `description`, `url` props; resolves absolute URLs via `Astro.site` +
   `absoluteSiteUrl`; emits 10 meta tags into the `head` slot.
5. Add `<link rel="icon" type="image/x-icon">` alongside the SVG favicon in
   Layout.astro.
6. Replace the hardcoded archive href in `[slug].astro` with
   `journalArchiveUrl(paper.journal_initials)`.
7. Mount `<SocialMeta slot="head">` in article (type=article), archive
   (type=website), and directory (type=website) pages.
8. Write `tests/seo.test.ts` (3-tier) and run the full suite.

### Data Flow

- **Input:** `ogImageUrl` (from brand.ts) + `Astro.site` (from astro.config.mjs)
  + page-level `title`/`description`/`url`.
- **Transform:** `socialImageUrl(site)` → `absoluteSiteUrl(ogImageUrl, site)`
  → `new URL('/journals/assets/social/amssrn-og.png', 'https://amssr.org')`
  → `'https://amssr.org/journals/assets/social/amssrn-og.png'`.
- **Output:** 10 `<meta>` tags per page in `<head>`, one ICO favicon `<link>`,
  one `<a href={journalArchiveUrl(...)}>` back-link.

### Dependencies

- Upstream: `astro.config.mjs` `site` value (already `https://amssr.org`).
- Upstream: `deployment-config.mjs` `PUBLIC_ASSET_PREFIX` (already `"/journals"`).
- Upstream: `public/_redirects` (already rewrites `/journals/assets/*` → `/assets/*`).
- Upstream: `src/lib/schemas.ts` `Paper` type (for page props).
- Upstream: `src/utils/papers.ts` `journalArchiveUrl` (already exists).
