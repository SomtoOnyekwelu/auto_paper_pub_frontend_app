### Why 1.2 (asset-base + domain rename) is the Next One
- **Priority 1 (MVP value):** the live site at `amssr.org/journals/*` renders as bare text because every root-relative asset URL (`/favicon.svg`, `/assets/*.css`, `/assets/*.js`) resolves against `amssr.org` (address-bar origin) instead of the Pages origin the Worker fetches. A styled, branded paper page is the core user-visible deliverable.
- **Priority 2 (critical-path blocker):** Google Scholar crawling and author trust both depend on styled pages with working assets; the `/journals/` URL scheme must be stable and canonical.
- **Priority 3 (zero upstream blockers):** page move (executor working tree) is done; `base` config + rename are pure frontend config + a few backend reference strings.
- **Priority 4 (MVP necessary):** yes — bare-text pages are broken UX; the wrong domain in sitemap/robots/meta actively harms indexing.
