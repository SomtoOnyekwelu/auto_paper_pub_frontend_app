# Challenge: Article Landing Page & Data Ingestion

ID: 1.0 · Status: In Progress (NEXT ONE) · Last Updated: 2026-07-26

## The Core Problem
Serve a single published paper to humans AND the Google Scholar crawler from one static HTML page: consume the backend's structured JSON + pre-calculated Highwire tags, validate them at build time, render with NIH/PubMed readability, inject exhaustive Highwire meta tags, and link the PDF galley through a local-looking URL the Edge Proxy resolves — with zero client JS, zero runtime DB, and perfect crawler fidelity.

## Constraints & Boundaries
- Astro 7 (`output: 'static'`), zero client JS.
- Data: `src/data/journals.json` (array), `src/data/themes.json` (keyed object), `src/data/papers/{new,published}/<id>.json`.
- All incoming JSON validated by Zod at BUILD time — an invalid file halts the build (Zero-Tolerance gate).
- Highwire tags exact: `citation_publication_date` as `YYYY/M/D` (NOT ISO); one `<meta>` per author / ORCID / institution; raw DOI (no `https://`); ORCID as full URL.
- Abstract MUST be visible in `<body>` (not behind a toggle).
- Visual fallback hierarchy: `<h1>` title > `<h2>`/`<h3>` authors > `<small>` journal/issue.
- `citation_pdf_url` rendered verbatim; the Edge Proxy (Challenge 1.2) proxies the binary from Supabase.
- `max-w-prose` serif abstract; Merriweather/Inter per journal, overridden from `themes.json` (Lora for grjaf/grjhpa).
- ≤ 7 plain-HTML `<a>` clicks from `/journals/` to the article.
- The frontend CONSUMES the backend's slug; it does NOT generate one.

## Inclusion Criteria
- Zod schemas in `src/lib/schemas.ts` (journals, themes, paper + Highwire) — canonical, used by both the build and the tests.
- Direct-import + Zod-validate modules for journals/themes (`src/lib/journals.ts`, `src/lib/themes.ts`) — single-file contracts preserved.
- Content Layer `papers` collection (`src/content.config.ts`) via `glob` over `new/`+`published/`; strict validation performed in `getStaticPaths` via `paperSchema.parse` (build-time gate, Zod error names the offending field).
- Dynamic route `src/pages/journals/[journal_initials]/[slug].astro` + `getStaticPaths`.
- `src/components/SeoHead.astro` — Highwire meta injection.
- `src/layouts/Layout.astro` — per-journal CSS-variable injection.
- `src/utils/papers.ts` — pure URL helpers.

## Exclusion Criteria
- Journal directory / archive pages → Challenge 1.1.
- Deployment / edge rewrite / sitemap / robots → Challenge 1.2.
- Author profile pages → MVP 2.
- Slug generation → backend (never frontend).
- Real-time SSR / live DB → permanently deferred.

## History & Decisive Decisions
- **Astro 7 vs brief's "Astro v5":** keep Astro 7 (installed, newer). Content Layer / Zod / SSG APIs are stable across 5→7.
- **No `base: '/journals'`:** `base` + `src/pages/journals/…` would produce `/journals/journals/…`, breaking the data contract's own URLs. The host routes `/journals/*` to this build; `/` belongs to the parent org (out of scope). Cleanest URL math; Hand-Sanitizer for links/sitemap.
- **1 collection (papers) + 2 validated imports (journals/themes), not "3 collections":** the journals/themes contract is one file each; `file()` array-splitting is ambiguous in the docs, so we direct-import + `schema.parse` them at module load. Zod still validates at build (Zero-Tolerance). Flagged to the product owner for review.
- **`@fontsource/lora` added:** themes use Lora serif for grjaf/grjhpa; without it those journals would silently fall back to Merriweather.

## Living Implementation Plan

### Strategy Overview
Build the data-ingestion + contract layer first (it is the failure surface everything else rides on), then the article route, then the shared Layout/SeoHead. Validate every JSON at build time via Zod so a malformed paper halts the build naming the field — that is the Zero-Tolerance gate the teachings demand. Render with semantic HTML and Tailwind utilities that read per-journal CSS variables, so multi-tenant theming is a data problem, not a code problem.

### Data Flow
- **Input:** `journals.json` (array), `themes.json` (keyed object), `papers/{new,published}/<id>.json`.
- **Transform:** Zod-validate at build → `papers` Content Collection + validated journals/themes modules → `getStaticPaths` over papers (strict `parse` + referential-integrity check) → Layout injects the paper's journal theme CSS vars → SeoHead emits Highwire meta → body renders title / authors / abstract / PDF link with the visual hierarchy.
- **Output:** one static HTML file per paper at `/journals/[initials]/[slug]/index.html` with exhaustive Highwire `<head>` meta and a visible abstract + PDF download `<a>`.

### Dependencies
- Upstream: backend JSON output (samples stand in for MVP).
- Downstream: 1.1 (archive links to the article) and 1.2 (sitemap lists the article; Edge Proxy serves the PDF).

### Step-by-Step Execution
1. `src/lib/schemas.ts` (Zod: journal/theme/paper/Highwire + regex + refines).
2. `src/lib/journals.ts`, `src/lib/themes.ts` (validate-on-import + lookup).
3. `src/content.config.ts` (papers `glob` collection, loose schema; strict parse in code).
4. `src/styles/global.css` (Tailwind v4 `@theme`), `astro.config.mjs` (site/static/sitemap/tailwind vite), `public/robots.txt`.
5. `src/layouts/Layout.astro` (per-journal CSS-var injection).
6. `src/components/SeoHead.astro` (one `<meta>` per Highwire field; per-author split).
7. `src/pages/journals/[journal_initials]/[slug].astro` (getStaticPaths + page + visible abstract + PDF button).
8. `src/pages/journals/index.astro` + `src/pages/journals/[journal_initials]/index.astro` (Challenge 1.1, built now for link coherence).
9. `src/utils/papers.ts` + Vitest/fast-check 3-tier tests (`tests/`).
10. `npm install` (zod, @fontsource/lora, vitest, fast-check) → `astro build` green → `vitest run` green.

## Data Representation Study: ingestPaper (build-time validation)

### Phase 1 — Formal Input Breakdown & Concretization
`paper JSON`:
- P1 valid → `papers/new/8492.json` (brief's exact values).
- P2 missing `title` → copy of 8492, `title` removed.
- P3 ISO date → `citation_publication_date: "2026-07-20"`.
- P4 https DOI → `"https://doi.org/10.1234/grjbm.v6i2.102"`.
- P5 bare ORCID → `"0000-0002-1825-0097"`.
- P6 non-parallel author arrays → `authors` length 2, `citation_author` length 1.
- P7 unknown journal → `journal_initials: "xxxx"`.
- P8 title-based slug → `"effect-of-monetary-policy-on-financial-services"`.
- P9 empty authors → `authors: []`.
- P10 external pdf url → `"https://supabase.host/galley.pdf"`.

### Phase 2 — Conceptual Mapping (domain insights)
- Slug shape: frontend does not generate slugs but must reject shapes the backend never emits: `^[0-9]+(-[a-z0-9][a-z0-9-]*)?$` — a numeric id, optionally followed by `-` and a lowercase body that may contain inner hyphens (real multi-word keywords like `social-progress` do). Accepts `8492-monetary-policy-finance` and `1045-fiscal-policy-social-progress`; rejects title-based slugs lacking the numeric id (`effect-of-monetary-policy-...`). NOTE: corpus Part 3 §7 says "at most 2 keywords" with `{0,2}` — but the brief's canonical slug uses 3 and real compound keywords contain inner hyphens, so the live spec is boundary-shaped, not keyword-count-shaped. Logged in `teachings to agent/0.0-teachings-corpus-index.md`.
- DOI raw-prefix: regex must accept lowercase (corpus bug — corrected here).
- ORCID full-URL required.
- `citation_author` / `citation_author_orcid` / `citation_author_institution` must be parallel (one entry per author).
- `authors[]` length must equal `citation_author[]` length.
- `journal_initials` must exist in `journals.json` (referential integrity — checked in `getStaticPaths`).

### Phase 3 — Cross-Product (intended behavior)
- CP1 (P1) → parse OK, page rendered.
- CP2 (P2) → Zod throws naming `title`; build halts.
- CP3 (P3) → throws naming `citation_publication_date` (must be YYYY/M/D).
- CP4 (P4) → throws naming `citation_doi` (raw prefix only).
- CP5 (P5) → throws naming ORCID.
- CP6 (P6) → throws naming the parallel-array invariant.
- CP7 (P7) → `getStaticPaths` throws `Unknown journal initials` (referential integrity).
- CP8 (P8) → throws naming `slug`.
- CP9 (P9) → throws (min 1 author).
- CP10 (P10) → throws naming `citation_pdf_url` (must be local-looking).

### Phase 4 — Output Space
Either (a) a parsed `Paper` (success → page rendered) or (b) a thrown ZodError (build halts, message printed). No silent leniency.

### Exact Format Specifications
- DOI: `^10\.\d{4,9}/[-._;()/:A-Za-z0-9]+$` · Valid `10.1234/grjbm.v6i2.102` · Invalid `https://doi.org/10.1234/grjbm.v6i2.102`
- ORCID: `^https://orcid\.org/\d{4}-\d{4}-\d{4}-\d{3}[\dX]$` · Valid `https://orcid.org/0000-0002-1825-0097` · Invalid `0000-0002-1825-0097`
- ISSN: `^\d{4}-\d{3}[\dX]$` · Valid `2811-1745`
- Publication date: `^\d{4}/\d{1,2}/\d{1,2}$` · Valid `2026/7/20` · Invalid `2026-07-20`
- Slug: `^[0-9]+(-[a-z0-9]+){0,3}$` · Valid `8492-monetary-policy-finance` (3 keywords) · Invalid `effect-of-monetary-policy-on-financial-services`
- citation_pdf_url: `^/journals/[a-z]+/[0-9a-z-]+/galley\.pdf$` · Valid `/journals/grjbm/8492-monetary-policy-finance/galley.pdf`
